    NKI validation status¶

    A snapshot of how each sub-project's current release was validated, and where it stands on Phase 1 — the "NKI kernels replace stubs and match the PyTorch reference on real trn1/trn2 hardware" milestone.

    Four gates, in order of how cheaply they can be run:

    1. Simulator gate — nki.simulate(kernel)(numpy_args) runs the NKI program on CPU with no device and no NEFF compile. Exercised in every PR via the nki-simulator CI job on ubuntu-latest across all six libraries. Catches Python-layer correctness, shape mismatches, and API drift.
    2. Conformance gate — tests/test_conformance.py in every library checks each public API against an independent reference (see below). Runs on CPU in every PR, and on the device by hand.
    3. Hardware gate — @pytest.mark.neuron tests, run manually by maintainers on Trainium (Trn2 for the native path, trn1 for the XLA path) via scripts/run_neuron_tests.sh. There is no hardware CI. Catches MLIR-verifier issues, numerical behavior, and real NEFF compile.
    4. Canonical reference — published spec vectors, or scipy / PySCF / LAPACK / ducc0 agreement, depending on the library.

    Per-kernel details live in each sub-project's docs/architecture.md. Per-phase definitions live in the suite roadmap.

    Current releases on Trn2¶

    Each current PyPI release was validated on a trn2.3xlarge with public Neuron SDK 2.33 (TorchNeuron public beta, torch 2.14, NKI 0.7.0, neuronx-cc 2.28), LNC=2, one logical core per process. Each validation ran the release's pytest -m neuron suite with the NKI trace cache off and on, the device conformance suite (--backend nki --conformance-device neuron), the CPU suite in a clean CPU-only venv, and the installed PyPI wheel. The records are comments on #35:

    trnblas 0.13.0 2026-11-10, window 6 comment 263 passed, 0 failed 2022: complex mv unsupported and device float64 at fp32 (2012), test tolerance (8), harness (2); no fp32 / bf16 / fp16 failures
    trnrand 0.14.0 2026-11-03, window 4 comment 407 passed, 0 failed 5: the documented Poisson normal approximation at λ ≥ 20 (trnrand#88)
    trnsolver 0.23.0 2026-11-10, window 6 comment (hold) 137 passed, 0 failed 100: complex linalg unsupported (41), device float64 at fp32 (59); plus 1 xfail, device float64 residual tolerance (trnsolver#144)
    trnsparse 0.16.1 2026-11-10, window 6 comment (0.16.0: comment) 317 passed, 0 failed (0.16.0: 4 GiB opt-in 2/2) 85: complex mv unsupported (64), device float64 at fp32 (12), harness (8), fp16 sqrt ulp (1)

    Every device conformance failure in these runs is in a documented platform category, a test-harness limit or a documented approximation, and none is new against the window-4 baselines. The platform categories are on precision and platform limits. The window-3 audit and scoreboard, and the window-4 conformance triage, set those baselines.

    Conformance against independent references¶

    The suites used to test the NKI path against the library's own pytorch path. That passes any bug in code both paths share: argument parsing, a planner, a host wrapper. Since November 2026 every library also has tests/test_conformance.py (trnsci#105). Each public API is checked against a reference that shares no code with it (torch.fft, torch.einsum, torch.linalg, scipy or a dense formula, in float64 on the host), at awkward sizes (1, 2, primes, 127 and 129 around the tile, 513, 1000) and with non-default keywords, dtypes, strides, empty shapes, out=, aliasing and autograd. The same cases run in CPU CI and, by hand, on the device. The audits that led to them found about 60 silent wrong-result bugs in released versions; each README lists them under "Known issues in earlier releases" (the post).

    Native TorchNeuron dispatch¶

    All six libraries ship native TorchNeuron dispatch (nki_op on the neuron device) next to the PyTorch/XLA path; the native ports merged on 2026-10-30. On the native device each library's auto dispatch sends an op to an NKI kernel only where the kernel measured faster than aten on the device, and to aten otherwise. Dense GEMMs (trnblas, except the DF-MP2 half-transform) and plain einsum matmul / bmm (trntensor) go to aten; the fused kernels (DF-MP2 pair energy, AO→MO, DF J/K, BSR SpMM, the GP kernel operator, block-sparse attention, the SHT Legendre stage) are where NKI wins. trnfft has no aten alternative to route to, because torch.fft doesn't run on the device. float64 follows the suite policy. In most libraries a kernel error falls back to torch with a warning unless <LIB>_REQUIRE_NKI=1 is set.

    Scoreboard and evidence: trnsci#35. Platform policy: installation.

    Legend:

    • ✅ Hardware-validated — kernels pass @pytest.mark.neuron on hardware (trn1 on the XLA path, Trn2 on the native path). On the native device, auto picks the NKI kernel where it measured faster than aten.
    • 🕑 Simulator-validated — kernels pass nki-simulator CI; hardware runs queued. PyTorch is the default until hardware passes.
    • 🚧 Simulator-validated, upstream-blocked — kernels compile and run; the library has a named, trackable NKI primitive gap preventing numerically-correct hardware output. See the blog retrospective for specifics.

    Cross-suite infrastructure¶

    • NKI 0.3.0 migration complete across all six libraries. Coordination tracked in trnsci/trnsci#5. Narrative: The dev loop just got a lot shorter.
    • nki-simulator CI gate on ubuntu-latest for every library. Fast iteration for Python-layer correctness; does not replace hardware for MLIR-verifier or numerical-behavior checks.
    • Hardware validation runs manually: per-repo scripts/run_neuron_tests.sh against a <repo>-ci-trn1 instance for the XLA path, and booked Trn2 windows for the native path, logged on #35.
    • Off-box compile caches. NEFFs compiled on a CPU host are reused on the device (trnsci#118, scripts/warm_neuron_cache.py), so hardware windows don't start cold.

    Looking ahead¶

    • Phase 1 trackers are closed for all six libraries. trnrand's Philox kernel, long attributed to aws-neuron-sdk#1308, was failing on a saturating int32/uint32 cast in the kernel itself; trnrand 0.8.0 fixed it (trnrand#56).
    • Phases 2–5 (precision, single-chip perf, multi-chip, generation-specific optimization) build on top of Phase 1 per the roadmap and are tracked in the phase milestones of each repository. The workload-level results are on exemplars.
    • At TorchNeuron general availability the XLA path is deprecated on Trn2/Trn3 and every library is re-validated on the GA SDK (GA checklist, #136).

    Design RFCs¶

    Sub-projects with published design docs for upcoming phases:

    • trnblas: fused DF-MP2 pair-energy kernel (Phase 3) — collapse (T*(2T−T.T)/denom).sum() into one SBUF-resident Vector+Scalar pass; targeted 3–6× on the DF-MP2 hot path. Shipped as pair_energy_sym; on Trn2 it measures 1.8× faster than aten (an earlier 92× figure was wrong, trnblas#57).
    • trnrand: SBUF-resident streaming Generator (Phase 3) — pre-compiled multi-distribution kernel with pipelined GpSimd / Vector / Scalar engines.
    • trnrand: counter-partitioned multi-chip RNG (Phase 4) — bit-exact cross-cluster-size RNG via Philox counter-space partitioning.

    Maintenance¶

    This page is updated when a library releases (the current-releases table) and when a Phase 1 tracker closes (or opens, for any new sub-project added to the suite). Historic state lives in the git history — no versioning beyond that.
